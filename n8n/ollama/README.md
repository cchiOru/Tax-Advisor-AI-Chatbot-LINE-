# การตั้งค่า Ollama สำหรับระบบนี้

## ปัญหาที่ต้องแก้ก่อนใช้ Typhoon

Ollama ตั้งหน้าต่างบริบทเริ่มต้นไว้ที่ **4,096 โทเคน** และเมื่อข้อมูลนำเข้าเกินขนาดนั้น
**Ollama จะตัดข้อมูลส่วนหน้าทิ้งโดยไม่แจ้งเตือนใด ๆ** ไม่มี error ไม่มีคำเตือน

ในระบบนี้ ข้อมูลส่วนหน้าคือ

1. คำสั่งระบบ (2,276 ตัวอักษร) — บอกว่าแบบจำลองเป็นใคร ต้องทำอะไร ห้ามทำอะไร
2. ตัวบทกฎหมายที่ค้นมาจากฐานข้อมูล (สูงสุด 3 รายการ)
3. นิยามเครื่องมือคำนวณภาษี

เมื่อสามอย่างนี้ถูกตัดทิ้ง แบบจำลองจะไม่รู้ว่าตัวเองเป็นที่ปรึกษาภาษี ไม่เห็นกฎหมาย
และไม่รู้ว่ามีเครื่องคำนวณให้เรียกใช้ **อาการที่เห็นคือตอบเงียบ ตอบมั่ว
หรือพิมพ์ข้อมูลดิบของเครื่องมือออกมาให้ผู้ใช้เห็น**

ภาษาไทยกินโทเคนมากกว่าภาษาอังกฤษหลายเท่า ปัญหานี้จึงเกิดกับระบบภาษาไทยง่ายกว่ามาก

> ข้อควรรู้เพิ่มเติม: ปลายทางแบบ OpenAI-compatible (`/v1/chat/completions`)
> ซึ่งเป็นทางที่ระบบนี้เรียกใช้ ไม่รับค่า `num_ctx` ที่ส่งไปในคำขอ
> การตั้งค่าจึงต้องทำที่ตัวแบบจำลองเอง ด้วยวิธีด้านล่าง

## วิธีแก้

สร้างแบบจำลองที่ตั้งหน้าต่างบริบทไว้แล้ว

```powershell
cd D:\project
ollama create typhoon-tax -f n8n/ollama/Modelfile.typhoon-tax
```

ตรวจว่าสร้างสำเร็จ

```powershell
ollama list
ollama show typhoon-tax
```

จากนั้นตั้งค่าใน `.env`

```
TYPHOON_MODEL=typhoon-tax
ACTIVE_MODEL_NAME=typhoon-tax
```

และในโหนด **Ollama Chat Model** ของ n8n ให้เปลี่ยนแบบจำลองเป็น `typhoon-tax`

## วัดผลซ้ำหลังแก้

```powershell
node evaluation/run-accuracy-test.js --model=typhoon --fresh
```

ต้องใส่ `--fresh` เพราะผลเดิมวัดจากแบบจำลองคนละตัว นำมาปนกันไม่ได้

## การเปรียบเทียบก่อน-หลัง มีค่าต่อปริญญานิพนธ์

ผลก่อนแก้กับหลังแก้เป็นหลักฐานเชิงประจักษ์ว่า **การตั้งค่าโครงสร้างพื้นฐาน
ส่งผลต่อความแม่นยำของระบบไม่แพ้ตัวแบบจำลองเอง** ซึ่งเป็นข้อค้นพบที่มีน้ำหนัก
กว่าการรายงานเพียงว่าแบบจำลองไหนแม่นกว่ากัน จึงควรเก็บผลทั้งสองชุดไว้
