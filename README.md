## ปัญหาที่ตั้งต้น

ผู้มีเงินได้จำนวนมากไม่รู้ว่าตนเองต้องยื่นภาษีหรือไม่ ต้องเสียเท่าไร และลดหย่อนอะไรได้บ้าง
ช่องทางที่มีอยู่ตอบโจทย์ไม่ครบ

- **เว็บไซต์กรมสรรพากร** มีข้อมูลครบแต่เป็นภาษากฎหมาย ผู้ใช้ทั่วไปอ่านแล้วตีความเองไม่ได้
- **สายด่วน 1161** ตอบได้ตรงจุดแต่จำกัดเวลาราชการ และต้องรอสาย
- **สำนักงานบัญชี** ตอบได้ดีที่สุดแต่มีค่าใช้จ่าย ไม่คุ้มกับคำถามเล็ก ๆ
- **แชตบอต AI ทั่วไป** ตอบทันทีและอ่านง่าย แต่**ตัวเลขเชื่อไม่ได้** และตรวจสอบที่มาไม่ได้

ข้อสุดท้ายคือปัญหาที่งานนี้มุ่งแก้

## ปัญหาแกนกลาง แล้วเราแก้อย่างไร

แบบจำลองภาษาขนาดใหญ่ให้คำตอบที่ **อ่านลื่นและดูน่าเชื่อถือ** แต่เมื่อเป็นเรื่องตัวเลข
มันจะคำนวณผิดโดยที่ยัง**อ้างมาตราถูกต้อง** ซึ่งเป็นความผิดพลาดชนิดที่ผู้ใช้จับไม่ได้เลย

ตัวอย่างจริงที่วัดได้ระหว่างพัฒนา เมื่อระบบคิดเลขเอง มันอ้างมาตรา 47(1)(ง) ถูกต้อง
แต่ลืมหักค่าใช้จ่าย 100,000 บาท และลืมค่าลดหย่อนส่วนตัว 60,000 บาท

วิธีแก้ที่งานนี้เสนอคือ **ย้ายสิ่งที่ต้องถูกต้องออกจากแบบจำลองภาษา ไปไว้ในโค้ดที่ทดสอบได้**

| หน้าที่ | ใครทำ | ตรวจสอบอย่างไร |
|---|---|---|
| เข้าใจคำถามภาษาไทยที่ผู้ใช้พิมพ์มา | แบบจำลองภาษา | วัดด้วยชุดคำถาม 115 ข้อ |
| **คำนวณภาษี เงินเพิ่ม ค่าปรับ** | **โค้ดที่เขียนเอง** | **ชุดทดสอบหน่วย 43 ข้อ ผ่านทั้งหมด** |
| หาเนื้อหากฎหมายที่เกี่ยวข้อง | การจับคู่คำสำคัญกับฐานความรู้ | วัดว่าค้นเจอ 100% |
| เรียบเรียงเป็นภาษาที่คนทั่วไปอ่านรู้เรื่อง | แบบจำลองภาษา | วัดความยาวและรูปแบบคำตอบ |
| **บังคับให้มีคำเตือนทุกคำตอบ** | **โค้ดหลังบ้าน** | **ชุดทดสอบ 35 ข้อ ผ่านทั้งหมด** |

## สิ่งที่ทำให้ระบบนี้ต่างจากการถาม ChatGPT หรือ Gemini โดยตรง

1. **ตัวเลขมาจากโค้ด ไม่ได้มาจาก AI** ถามคำถามเดิมสิบครั้งได้คำตอบเดิมทุกครั้ง
2. **อ้างมาตราได้ทุกคำตอบ** เพราะเนื้อหามาจากฐานความรู้ที่ระบุแหล่งที่มาไว้ทุกรายการ
3. **ใช้ตัวเลขที่บังคับใช้จริง ไม่ใช่ตัวเลขในตัวบท** ตัวบทมาตรา 47(1)(ง) เขียนว่าเบี้ยประกันชีวิต
   หักได้ 10,000 บาท แต่ค่าที่ใช้จริงคือ 100,000 บาท ตามกฎกระทรวง ฉบับที่ 126
   ระบบถูกออกแบบไม่ให้หยิบตัวเลขจากตัวบทมาตอบ
4. **วัดความแม่นยำเป็นตัวเลขได้** พร้อมตัวชี้วัดความปลอดภัยว่ามีกี่ครั้งที่ตอบตัวเลขโดยไม่ผ่านเครื่องคำนวณ
5. **บันทึกทุกบทสนทนาไว้วิเคราะห์** ว่าใช้ข้อมูลรายการไหน ใช้เวลาเท่าไร เป็นคำถามประเภทใด
6. **รู้ขอบเขตของตัวเอง** เรื่องนอกภาษีจะปฏิเสธ เรื่องภาษีที่ไม่มีเครื่องมือคำนวณจะอธิบายหลักเกณฑ์
   แต่ไม่คำนวณให้

## ฐานข้อมูล

ระบบใช้ตารางกฎหมายสามชุด แยกหน้าที่กันชัดเจน ห้ามใช้ปนกัน

| ตาราง | จำนวน | ใช้ทำอะไร |
|---|---|---|
| `tax_law_knowledge` | 85 รายการ | **ใช้ตอบคำถามผู้ใช้** เรียบเรียงเป็นภาษาที่คนทั่วไปเข้าใจ ใช้ตัวเลขที่บังคับใช้จริงปี 2567 |
| `revenue_code_current` | 309 มาตรา | **ใช้ยกถ้อยคำของกฎหมาย** เมื่อผู้ใช้ถามถึงมาตราโดยตรง ดึงจากเว็บไซต์กรมสรรพากร |
| `revenue_code_sections` | ฉบับ พ.ศ. 2482 | **ไม่ใช้แล้ว** ตัวเลขล้าสมัยทั้งหมด เก็บไว้เป็นบันทึกการทดลอง |

> **ข้อควรระวังที่สำคัญที่สุดของระบบ** ห้ามนำตัวเลขจาก `revenue_code_current` ไปตอบคำถามเรื่องเงิน
> เพราะตัวบทหลายมาตราถูกกฎกระทรวงหรือพระราชกฤษฎีกาแก้ไขค่าในภายหลัง

แหล่งที่มาของข้อมูลทุกชุดบันทึกไว้ที่ [`docs/แหล่งอ้างอิงของระบบ.md`](docs/แหล่งอ้างอิงของระบบ.md)
รวมถึงข้อมูลที่เคยนำเข้าแล้วเลิกใช้ และข้อมูลที่พิจารณาแล้วแต่ยังไม่นำเข้า พร้อมเหตุผล

## ติดตั้งใหม่จากศูนย์

### สิ่งที่ต้องมี

- Docker Desktop
- Node.js 20 ขึ้นไป (ใช้รันชุดทดสอบ)
- Python 3.10 ขึ้นไป (ใช้สร้างเวิร์กโฟลว์และ Rich Menu)
- บัญชี LINE Official Account และ Messaging API channel
- API key ของ Google Gemini

### ขั้นตอน

```bash
git clone https://github.com/cchiOru/Tax-Advisor-AI-Chatbot-LINE-.git
cd Tax-Advisor-AI-Chatbot-LINE-

# 1. สร้างไฟล์ตั้งค่าจากตัวอย่าง แล้วเติมค่าจริงของตัวเอง
cp .env.example .env

# 2. เปิดบริการทั้งหมด
docker compose up -d

# 3. นำเข้าฐานความรู้
docker cp postgres/seed-tax-law.sql        tax-advisor-postgres:/tmp/
docker cp postgres/seed-tax-law-extra.sql  tax-advisor-postgres:/tmp/
docker cp postgres/seed-tax-law-full.sql   tax-advisor-postgres:/tmp/
docker cp postgres/seed-tax-law-cases.sql  tax-advisor-postgres:/tmp/
docker cp postgres/seed-tax-forms.sql      tax-advisor-postgres:/tmp/
docker cp postgres/seed-tax-law-deductions-detail.sql tax-advisor-postgres:/tmp/
for f in seed-tax-law seed-tax-law-extra seed-tax-law-full seed-tax-law-cases seed-tax-forms seed-tax-law-deductions-detail; do
  docker exec tax-advisor-postgres psql -U n8n_admin -d tax_advisor -f /tmp/$f.sql
done

# 4. ดึงตัวบทประมวลรัษฎากรฉบับปัจจุบันจากเว็บไซต์กรมสรรพากร
pip install requests beautifulsoup4
python postgres/import-revenue-code-current.py

# 5. สร้างไฟล์เวิร์กโฟลว์ แล้วนำเข้าใน n8n ที่ http://localhost:5678
python n8n/build-workflow.py

# 6. ติดตั้ง Rich Menu บน LINE
pip install pillow requests
python line/setup-rich-menu.py --clean
```

**ต้องทำด้วยมือหลังนำเข้าเวิร์กโฟลว์** ผูก credential ให้โหนด PostgreSQL ทั้ง 5 โหนด และโหนด Gemini
แล้วตั้ง Webhook URL ใน LINE Developers ให้ตรงกับที่อยู่ของ ngrok ปัจจุบัน

> **`.env` ไม่ได้อยู่ใน repository นี้โดยเจตนา** เพราะเก็บ API key และรหัสผ่านฐานข้อมูล
> ให้คัดลอกจาก `.env.example` แล้วเติมค่าของตัวเอง

## ข้อจำกัดที่ยอมรับไว้อย่างตรงไปตรงมา

1. **ยังไม่ควรเปิดให้ประชาชนทั่วไปใช้** อัตราการเรียกเครื่องคำนวณอยู่ที่ 94.9%
   ยังไม่ถึงเกณฑ์ 98% ที่ตั้งไว้ ระดับปัจจุบันเหมาะกับการสาธิตและทดลองกับกลุ่มเล็ก
2. **ครอบคลุมเฉพาะภาษีเงินได้บุคคลธรรมดา** ปีภาษี 2567 ยังไม่รองรับนิติบุคคลและภาษีมูลค่าเพิ่ม
   อย่างเต็มรูปแบบ
3. **แบบจำลองที่รันในเครื่องติดข้อจำกัดฮาร์ดแวร์** การ์ดจอที่ใช้พัฒนามีหน่วยความจำ 4 GB
   ตัวแบบจำลองใช้ 3.6 GB จึงต้องแบ่งงานไปรันบน CPU บางส่วน ทำให้ช้ากว่าที่ควรเป็น
   บันทึกผลการทดลองปรับค่าไว้ครบใน `n8n/ollama/Modelfile.typhoon-tax`
4. **คำตอบยังไม่ใช่คำวินิจฉัยทางกฎหมาย** ทุกคำตอบจึงมีคำเตือนให้ตรวจสอบกับกรมสรรพากรบังคับติดไว้เสมอ
