# ระบบที่ปรึกษาด้านภาษีด้วยปัญญาประดิษฐ์บนไลน์ โดยใช้ระบบอัตโนมัติ

Development of an AI-Based Tax Advisory System on LINE Using Workflow Automation

ปริญญานิพนธ์ระดับปริญญาตรี ภาควิชาวิทยาการคอมพิวเตอร์และเทคโนโลยีสารสนเทศ
คณะวิทยาศาสตร์ มหาวิทยาลัยนเรศวร

ผู้จัดทำ นายยศกร แจ้งมณี และนางสาวณัฏฐณิชา ป้องป้อม
อาจารย์ที่ปรึกษา ผู้ช่วยศาสตราจารย์ ดร.สัญญา เครือหงษ์

ปีภาษีที่ระบบใช้อ้างอิงคือ 2567
สถานะปัจจุบันเป็นต้นแบบที่ผ่านการวัดผลแล้ว ใช้สาธิตและทดลองกับกลุ่มเล็กได้ แต่ยังไม่เปิดให้บุคคลทั่วไป

## ที่มาของปัญหา

คนจำนวนมากไม่รู้ว่าตัวเองต้องยื่นภาษีหรือไม่ ต้องเสียเท่าไร และลดหย่อนอะไรได้บ้าง
ช่องทางที่มีอยู่ตอนนี้ยังตอบไม่ครบ

เว็บไซต์กรมสรรพากรมีข้อมูลครบ แต่เขียนด้วยภาษากฎหมาย คนทั่วไปอ่านแล้วตีความเองไม่ได้
สายด่วน 1161 ตอบได้ตรงจุด แต่จำกัดเวลาราชการและต้องรอสาย
สำนักงานบัญชีตอบได้ดีที่สุด แต่มีค่าใช้จ่าย ไม่คุ้มถ้าเป็นคำถามเล็กน้อย
ส่วนแชตบอตปัญญาประดิษฐ์ทั่วไปตอบทันทีและอ่านง่าย แต่ตัวเลขเชื่อไม่ได้ และตรวจสอบที่มาไม่ได้

ข้อสุดท้ายคือสิ่งที่โครงงานนี้ต้องการแก้

## แนวคิดของระบบ

แบบจำลองภาษาขนาดใหญ่ตอบคำถามได้ลื่นและอ่านเข้าใจง่าย แต่พอเป็นเรื่องตัวเลขมันคำนวณผิดได้
โดยที่ยังอ้างมาตราถูกต้อง ผู้ใช้จึงไม่มีทางรู้เลยว่าคำตอบผิด

ตัวอย่างที่พบระหว่างพัฒนา เมื่อปล่อยให้ระบบคิดเลขเอง มันอ้างมาตรา 47(1)(ง) ได้ถูก
แต่ลืมหักค่าใช้จ่าย 100,000 บาท และลืมค่าลดหย่อนส่วนตัว 60,000 บาท

โครงงานนี้จึงแยกงานออกเป็นสองส่วน ส่วนที่ต้องถูกต้องแน่นอนเขียนเป็นโค้ดที่มีชุดทดสอบกำกับ
ส่วนที่ต้องยืดหยุ่นจึงปล่อยให้แบบจำลองภาษาทำ

| หน้าที่ | ใครทำ | ตรวจสอบอย่างไร |
|---|---|---|
| เข้าใจคำถามภาษาไทยที่ผู้ใช้พิมพ์มา | แบบจำลองภาษา | ชุดคำถามทดสอบ 115 ข้อ |
| คำนวณภาษี เงินเพิ่ม ค่าปรับ | โค้ดที่เขียนเอง | ชุดทดสอบหน่วย 43 ข้อ |
| หาเนื้อหากฎหมายที่เกี่ยวข้อง | จับคู่คำสำคัญกับฐานความรู้ | วัดอัตราการค้นเจอ |
| เรียบเรียงให้คนทั่วไปอ่านรู้เรื่อง | แบบจำลองภาษา | วัดความยาวและรูปแบบคำตอบ |
| บังคับให้มีคำเตือนทุกคำตอบ | โค้ดหลังบ้าน | ชุดทดสอบ 35 ข้อ |

## ผลการทดลอง

### การสั่งด้วยคำสั่งระบบอย่างเดียวไม่พอ

ตอนแรกใช้วิธีเขียนกฎลงในคำสั่งระบบทั้งหมด ผลออกมาว่าแบบจำลองภาษาทำตามบ้างไม่ทำตามบ้าง
เมื่อย้ายกฎเดียวกันไปบังคับด้วยโค้ด ผลดีขึ้นชัดเจน

| ตัวชี้วัด | สั่งด้วยคำสั่งระบบ | บังคับด้วยโค้ด |
|---|---|---|
| เรียกเครื่องคำนวณเมื่อโจทย์ต้องใช้ตัวเลข | 79.5% | 94.9% |
| มีคำเตือนต่อท้ายคำตอบ | ขาดเป็นบางครั้ง | 100% |
| ความยาวคำตอบเฉลี่ย | 729 ตัวอักษร | 404 ตัวอักษร |

ระหว่างทดลองยังพบด้วยว่าคำสั่งระบบยิ่งยาว แบบจำลองภาษายิ่งทำตามน้อยลง ซึ่งสวนกับที่คาดไว้ตอนแรก

| ความยาวคำสั่งระบบ | จำนวนครั้งที่ไม่เรียกเครื่องคำนวณ |
|---|---|
| 2,275 ตัวอักษร | 2 |
| 3,321 ตัวอักษร | 3 |
| 4,017 ตัวอักษร | 8 |

จึงเขียนคำสั่งระบบใหม่ให้สั้นลง และย้ายกฎที่สำคัญที่สุดไปไว้ต้นข้อความ

### ความแม่นยำโดยรวม

วัดจากคำถาม 115 ข้อ ทุกข้ออ้างอิงตัวบทกฎหมายจริง

| ตัวชี้วัด | ผล | เกณฑ์ที่ตั้งไว้ |
|---|---|---|
| ตอบถูก | 88.7% (102 จาก 115) | 80–95% |
| เรียกเครื่องคำนวณเมื่อต้องใช้ | 94.9% | 98% ยังไม่ถึง |
| ค้นฐานความรู้เจอ | 100% | 95% |
| เวลาตอบเฉลี่ย | 30.3 วินาที | ไม่ได้ตั้งไว้ |
| ตอบเกิน 60 วินาที | 1 จาก 115 | 0 |

ก่อนปรับปรุงเรื่องความเร็ว เวลาตอบเฉลี่ยอยู่ที่ 67.6 วินาที และมี 62 ข้อจาก 115 ที่ใช้เวลาเกิน
60 วินาที ซึ่งเกินอายุของ reply token ของ LINE คือส่งคำตอบกลับไม่ทัน

ไฟล์ผลการวัดอยู่ที่ [`evaluation/results/published/`](evaluation/results/published/)

## ระบบนี้ต่างจากการถาม ChatGPT หรือ Gemini ตรงไหน

ระบบใช้ Gemini เป็นสมองอยู่แล้ว สิ่งที่เพิ่มเข้าไปคือกลไกที่ทำให้คำตอบตรวจสอบได้

ตัวเลขทุกตัวมาจากโค้ด ไม่ได้มาจากแบบจำลองภาษา ถามคำถามเดิมสิบครั้งได้คำตอบเดิมทุกครั้ง
เนื้อหาที่ใช้ตอบมาจากฐานความรู้ที่ระบุแหล่งที่มาไว้ทุกรายการ จึงอ้างมาตราได้เสมอ
และวัดความแม่นยำออกมาเป็นตัวเลขได้ พร้อมนับด้วยว่ามีกี่ครั้งที่ระบบตอบตัวเลขโดยไม่ผ่านเครื่องคำนวณ

อีกจุดที่ต่างคือระบบใช้ตัวเลขที่บังคับใช้จริง ไม่ใช่ตัวเลขที่เขียนอยู่ในตัวบท
ตัวบทมาตรา 47(1)(ง) เขียนว่าเบี้ยประกันชีวิตหักได้ 10,000 บาท แต่ค่าที่ใช้จริงคือ 100,000 บาท
ตามกฎกระทรวง ฉบับที่ 126 ระบบจึงถูกออกแบบไม่ให้หยิบตัวเลขจากตัวบทมาตอบ

นอกจากนี้ทุกบทสนทนาถูกบันทึกไว้ว่าใช้ข้อมูลรายการไหน ใช้เวลาเท่าไร เป็นคำถามประเภทใด
และระบบรู้ขอบเขตของตัวเอง เรื่องนอกภาษีจะปฏิเสธ ส่วนเรื่องภาษีที่ไม่มีเครื่องมือคำนวณรองรับ
จะอธิบายหลักเกณฑ์ให้แต่ไม่คำนวณตัวเลขให้

## ฐานข้อมูล

ระบบเก็บข้อมูลกฎหมายไว้สามตาราง แยกหน้าที่กันชัดเจนและห้ามใช้ปนกัน

| ตาราง | จำนวน | ใช้ทำอะไร |
|---|---|---|
| `tax_law_knowledge` | 85 รายการ | ใช้ตอบคำถามผู้ใช้ เรียบเรียงเป็นภาษาที่คนทั่วไปเข้าใจ ใช้ตัวเลขที่บังคับใช้จริงปี 2567 |
| `revenue_code_current` | 309 มาตรา | ใช้ยกถ้อยคำของกฎหมายเมื่อผู้ใช้ถามถึงมาตราโดยตรง ดึงจากเว็บไซต์กรมสรรพากร |
| `revenue_code_sections` | ฉบับ พ.ศ. 2482 | ไม่ใช้แล้ว ตัวเลขล้าสมัยทั้งหมด เก็บไว้เป็นบันทึกการทดลอง |

ข้อควรระวังที่สำคัญที่สุดของระบบคือห้ามนำตัวเลขจาก `revenue_code_current` ไปตอบคำถามเรื่องเงิน
เพราะตัวบทหลายมาตราถูกกฎกระทรวงหรือพระราชกฤษฎีกาแก้ไขค่าในภายหลัง

แหล่งที่มาของข้อมูลทุกชุดบันทึกไว้ที่ [`docs/แหล่งอ้างอิงของระบบ.md`](docs/แหล่งอ้างอิงของระบบ.md)
รวมถึงข้อมูลที่เคยนำเข้าแล้วเลิกใช้ และข้อมูลที่พิจารณาแล้วแต่ยังไม่นำเข้า พร้อมเหตุผลของแต่ละอย่าง

## ติดตั้งใหม่จากศูนย์

สิ่งที่ต้องมีก่อน คือ Docker Desktop, Node.js 20 ขึ้นไป, Python 3.10 ขึ้นไป,
บัญชี LINE Official Account ที่เปิด Messaging API แล้ว และ API key ของ Google Gemini

```bash
git clone https://github.com/cchiOru/Tax-Advisor-AI-Chatbot-LINE-.git
cd Tax-Advisor-AI-Chatbot-LINE-

# 1. สร้างไฟล์ตั้งค่าจากตัวอย่าง แล้วเติมค่าจริงของตัวเอง
cp .env.example .env

# 2. เปิดบริการทั้งหมด
docker compose up -d

# 3. นำเข้าฐานความรู้
for f in seed-tax-law seed-tax-law-extra seed-tax-law-full \
         seed-tax-law-cases seed-tax-forms seed-tax-law-deductions-detail; do
  docker cp postgres/$f.sql tax-advisor-postgres:/tmp/
  docker exec tax-advisor-postgres psql -U n8n_admin -d tax_advisor -f /tmp/$f.sql
done

# 4. ดึงตัวบทประมวลรัษฎากรฉบับปัจจุบันจากเว็บไซต์กรมสรรพากร
pip install requests beautifulsoup4
python postgres/import-revenue-code-current.py

# 5. สร้างไฟล์เวิร์กโฟลว์ แล้วนำเข้าใน n8n ที่ http://localhost:5678
python n8n/build-workflow.py

# 6. ติดตั้ง Rich Menu บน LINE
pip install pillow requests
python line/setup-rich-menu.py --clean
```

หลังนำเข้าเวิร์กโฟลว์ต้องทำอีกสองอย่างด้วยมือ คือผูก credential ให้โหนด PostgreSQL ทั้ง 5 โหนด
และโหนด Gemini แล้วตั้ง Webhook URL ใน LINE Developers ให้ตรงกับที่อยู่ ngrok ปัจจุบัน

ไฟล์ `.env` ไม่ได้อยู่ใน repository นี้ เพราะเก็บ API key และรหัสผ่านฐานข้อมูล
ให้คัดลอกจาก `.env.example` แล้วเติมค่าของตัวเองแทน

## ข้อจำกัดของระบบ

ยังไม่ควรเปิดให้ประชาชนทั่วไปใช้ เพราะอัตราการเรียกเครื่องคำนวณอยู่ที่ 94.9% ยังไม่ถึงเกณฑ์ 98%
ที่ตั้งไว้ ระดับปัจจุบันเหมาะกับการสาธิตและทดลองกับกลุ่มเล็กเท่านั้น

ระบบครอบคลุมเฉพาะภาษีเงินได้บุคคลธรรมดา ปีภาษี 2567 ยังไม่รองรับภาษีเงินได้นิติบุคคล
และภาษีมูลค่าเพิ่มอย่างเต็มรูปแบบ

แบบจำลองภาษาที่รันในเครื่องติดข้อจำกัดของฮาร์ดแวร์ การ์ดจอที่ใช้พัฒนามีหน่วยความจำ 4 GB
ส่วนตัวแบบจำลองใช้ 3.6 GB จึงต้องแบ่งงานบางส่วนไปรันบน CPU ทำให้ช้ากว่าที่ควรเป็น
ผลการทดลองปรับค่าต่าง ๆ บันทึกไว้ใน `n8n/ollama/Modelfile.typhoon-tax`

คำตอบของระบบไม่ใช่คำวินิจฉัยทางกฎหมาย ทุกคำตอบจึงมีคำเตือนให้ตรวจสอบกับกรมสรรพากรติดไว้เสมอ
