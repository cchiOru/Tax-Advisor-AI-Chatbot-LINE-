## ส่วน ก: ทำไมต้องเปรียบเทียบแบบจำลอง

### เหตุผลเชิงวิธีวิจัย

การเลือกแบบจำลองภาษาเป็นการตัดสินใจเชิงออกแบบที่สำคัญที่สุดอย่างหนึ่งของระบบ
งานวิจัยระดับปริญญาตรีที่ดีควรแสดงให้เห็นว่าการเลือกนั้นมีเหตุผลรองรับ ไม่ใช่เลือกเพราะสะดวก

การเปรียบเทียบยังตอบคำถามที่คณะกรรมการมักถามในการสอบป้องกัน เช่น
- ทำไมถึงเลือกแบบจำลองตัวนี้
- ถ้าใช้แบบจำลองภาษาไทยโดยเฉพาะจะดีกว่าไหม
- ระบบนี้ต้องพึ่งพาบริการเชิงพาณิชย์จากต่างประเทศหรือไม่ ถ้าไม่มีงบประมาณจะทำอย่างไร

### ตัวแปรที่ควบคุมในการทดลอง

เครื่องมือเปรียบเทียบในโปรเจกต์นี้ควบคุมให้ทุกอย่างเหมือนกันหมด ยกเว้นตัวแบบจำลอง

| ตัวแปร | สถานะ |
|---|---|
| ชุดคำถามทดสอบ | คงที่ 12 ข้อ เหมือนกันทุกแบบจำลอง |
| คำสั่งระบบ (System Prompt) | คงที่ ข้อความเดียวกันทุกตัวอักษร |
| นิยามเครื่องมือคำนวณ | คงที่ โครงสร้าง JSON เดียวกัน |
| ค่า temperature | คงที่ที่ 0.3 |
| วิธีเรียก API | คงที่ ใช้รูปแบบที่เข้ากันได้กับ OpenAI ทั้งหมด |
| **แบบจำลองภาษา** | **ตัวแปรต้น (สิ่งที่เปลี่ยน)** |

### ตัวชี้วัดที่วัด

| ตัวชี้วัด | ความหมาย | ทำไมถึงสำคัญ |
|---|---|---|
| อัตราการเรียกเครื่องมือสำเร็จ | คำถามที่ต้องคำนวณ แบบจำลองเรียกเครื่องมือหรือคำนวณเองมั่ว | ตัวชี้วัดที่สำคัญที่สุด ถ้าไม่เรียกเครื่องมือ ตัวเลขภาษีจะเชื่อถือไม่ได้ |
| ความถูกต้องของคำตอบ | ตัวเลขตรงกับที่กฎหมายกำหนด หรือมีคำสำคัญครบ | วัดคุณภาพคำตอบโดยรวม |
| เวลาตอบสนอง | มิลลิวินาที ตั้งแต่ส่งคำถามจนได้คำตอบ | ผู้ใช้บนไลน์คาดหวังคำตอบเร็ว |
| ส่วนเบี่ยงเบนมาตรฐานของเวลา | ความคงเส้นคงวาของความเร็ว | ระบบที่ช้าบ้างเร็วบ้างให้ประสบการณ์ที่แย่ |

## ส่วน ข: ตั้งค่า Google Gemini (โควตาฟรี)

### ข.1 ขอกุญแจ API

1. เปิดเบราว์เซอร์ไปที่ https://aistudio.google.com/apikey
2. ล็อกอินด้วยบัญชี Google (ใช้บัญชีเดียวกับที่ใช้ในมหาวิทยาลัยได้)
3. กดปุ่ม **Create API key**
4. ถ้าถามให้เลือกโปรเจกต์ ให้เลือก **Create API key in new project**
5. จะได้ข้อความยาวขึ้นต้นด้วย `AIza...` กด **Copy** เก็บไว้

> ไม่ต้องผูกบัตรเครดิต โควตาฟรีของ Gemini 2.5 Flash อยู่ที่ประมาณ
> 10 คำขอต่อนาที และ 250 คำขอต่อวัน ซึ่งเพียงพอสำหรับการทดสอบระบบและเก็บข้อมูลวิจัย
> แต่ถ้าทดสอบกับผู้ใช้จริงหลายสิบคนพร้อมกันในวันเดียว อาจชนเพดาน ให้กระจายเป็นหลายวัน

### ข.2 ใส่กุญแจลงไฟล์ `.env`

เปิดไฟล์ `D:\project\.env` ด้วย VS Code แล้วเพิ่มสองบรรทัดนี้ต่อท้าย:

```
GEMINI_API_KEY=AIza...ใส่ค่าที่คัดลอกมา
GEMINI_MODEL=gemini-2.5-flash
```

บันทึกไฟล์ แล้วรีสตาร์ท n8n เพื่อให้อ่านค่าใหม่:
```powershell
cd D:\project
docker compose restart n8n
```

### ข.3 เปลี่ยน n8n ให้ใช้ Gemini

1. เปิด http://localhost:5678 → เปิด workflow **Tax Advisor AI Chatbot (LINE) v2**
2. สร้าง credential ก่อน: ไปที่ `localhost:5678/home/credentials` → **Add Credential**
   → ค้นหา `Google Gemini` → เลือก **Google Gemini(PaLM) Api**
   → ใส่ API key → **Save** → ตั้งชื่อว่า `Gemini API`
3. กลับมาที่ workflow กดปุ่ม **+** ที่มุมขวาบนของผืนผ้าใบ ค้นหา `Google Gemini Chat Model` แล้วเพิ่มเข้ามา
4. เปิด node ที่เพิ่งเพิ่ม:
   - Credential: เลือก `Gemini API`
   - Model: เลือก `models/gemini-2.5-flash` (หรือพิมพ์เองถ้าเลือกจากรายการไม่ได้)
5. **ลบเส้นเชื่อมเดิม** ระหว่าง OpenAI Chat Model กับ AI Agent
   (คลิกที่เส้น แล้วกดปุ่มถังขยะที่ปรากฏขึ้น)
6. ลากเส้นจากจุดเชื่อมด้านบนของ Google Gemini Chat Model ขึ้นไปที่ช่อง **Chat Model** ใต้ AI Agent
7. กด **Ctrl+S** แล้วกด **Publish**

> **เคล็ดลับ:** อย่าลบ node OpenAI Chat Model ทิ้ง ปล่อยไว้เฉยๆ โดยไม่ต่อเส้น
> เวลาจะสลับกลับไปทดสอบเปรียบเทียบจะได้แค่ย้ายเส้นเชื่อม ไม่ต้องตั้งค่าใหม่

### ข.4 ทดสอบ

พิมพ์ใน LINE: `เงินเดือน 50000 ต่อเดือน จ่ายประกันสังคม 9000 ต้องเสียภาษีเท่าไหร่`

## ส่วน ค: ตั้งค่า Typhoon (แบบจำลองภาษาไทย รันในเครื่อง)

สเปกเครื่องที่ใช้ในงานวิจัยนี้คือ NVIDIA GeForce RTX 3050 Laptop ซึ่งมีหน่วยความจำกราฟิก 4 GB

| แบบจำลอง | ขนาดพารามิเตอร์ | พื้นที่ที่ใช้ | รันบนเครื่องนี้ได้ไหม |
|---|---|---|---|
| `scb10x/typhoon2.5-qwen3-4b` | 4 พันล้าน | ประมาณ 2.5 GB | ได้ (แนะนำ) |
| `scb10x/typhoon2.1-gemma3-4b` | 4 พันล้าน | ประมาณ 3 GB | ได้ |
| `scb10x/llama3.2-typhoon2-3b-instruct` | 3 พันล้าน | ประมาณ 2 GB | ได้ (เร็วกว่าแต่ความสามารถน้อยกว่า) |

ด้านการเรียกใช้เครื่องมือ (function calling) ให้แม่นยำขึ้น ซึ่งจำเป็นต่อสถาปัตยกรรมของระบบนี้

> จึงคาดว่าจะเรียกใช้เครื่องมือได้แม่นยำน้อยกว่าและตอบช้ากว่า
> ผลลัพธ์นี้เป็นข้อค้นพบที่มีคุณค่าในตัวเอง ควรรายงานตามจริงในบทที่ 4
> ไม่ใช่ความล้มเหลวของงานวิจัย

### ค.2 ติดตั้ง Ollama บน Windows

> ติดตั้งแบบปกติบน Windows โดยตรง **ไม่ต้องติดตั้งใน Docker**
> เพราะการส่งต่อการ์ดจอเข้า container บน Windows ยุ่งยากกว่ามาก

1. ไปที่ https://ollama.com/download เลือก **Windows** แล้วดาวน์โหลด
2. ดับเบิลคลิกไฟล์ที่โหลดมาเพื่อติดตั้ง (กด Next ไปเรื่อยๆ)
3. ติดตั้งเสร็จแล้ว Ollama จะทำงานอยู่เบื้องหลัง (เห็นไอคอนตัวลามะที่มุมขวาล่างของจอ)
4. เปิด PowerShell ตรวจสอบว่าใช้งานได้:
   ```powershell
   ollama --version
   ```

### ค.3 ดาวน์โหลดแบบจำลอง Typhoon

```powershell
ollama pull scb10x/typhoon2.5-qwen3-4b
```

ขั้นตอนนี้ดาวน์โหลดประมาณ 2.5 GB ใช้เวลาสักพักขึ้นกับความเร็วอินเทอร์เน็ต

> **ระวังพื้นที่ดิสก์:** เครื่องนี้มี SSD 256 GB ซึ่ง Docker ใช้ไปพอสมควรแล้ว
> ตรวจสอบพื้นที่ว่างก่อนด้วยการเปิด File Explorer แล้วดูที่ไดรฟ์ C:
> ควรมีที่ว่างอย่างน้อย 10 GB

ทดสอบว่าแบบจำลองทำงาน:
```powershell
ollama run scb10x/typhoon2.5-qwen3-4b "สวัสดี ช่วยแนะนำตัวสั้นๆ"
```
พิมพ์ `/bye` แล้ว Enter เพื่อออก

### ค.4 ตั้งค่าให้ n8n เชื่อมต่อ Ollama ได้

n8n ทำงานอยู่ใน container ส่วน Ollama ทำงานบน Windows โดยตรง
การเรียก `localhost` จากภายใน container จะไม่เจอ Ollama ต้องใช้ชื่อพิเศษแทน

1. เปิดไฟล์ `D:\project\.env` เพิ่มบรรทัดนี้:
   ```
   OLLAMA_BASE_URL=http://localhost:11434
   TYPHOON_MODEL=scb10x/typhoon2.5-qwen3-4b
   ```
   (สองบรรทัดนี้ใช้สำหรับสคริปต์เปรียบเทียบที่รันบน Windows โดยตรง)

2. ใน n8n ให้ตั้ง credential แยก:
   - ไปที่ `localhost:5678/home/credentials` → **Add Credential** → ค้นหา `Ollama`
   - ช่อง **Base URL** ใส่ `http://host.docker.internal:11434`
     (ชื่อนี้คือวิธีที่ container เรียกถึงเครื่อง Windows ที่รันมันอยู่)
   - **Save** แล้วตั้งชื่อว่า `Ollama Local`

3. เพิ่ม node ใน workflow:
   - กด **+** ค้นหา `Ollama Chat Model` แล้วเพิ่มเข้ามา
   - Credential: เลือก `Ollama Local`
   - Model: เลือกหรือพิมพ์ `scb10x/typhoon2.5-qwen3-4b`

4. สลับเส้นเชื่อมมาที่ node นี้เมื่อต้องการทดสอบ Typhoon (วิธีเดียวกับส่วน ข.3 ข้อ 5-6)

### ค.5 ถ้าเชื่อมต่อไม่ได้

ปัญหาที่พบบ่อยคือ Ollama ยอมรับการเชื่อมต่อจากเครื่องตัวเองเท่านั้น ทำให้ container เรียกไม่ได้
แก้โดยตั้งตัวแปรสภาพแวดล้อมของ Windows:

1. กด Start พิมพ์ `environment variables` เลือก **Edit the system environment variables**
2. กดปุ่ม **Environment Variables**
3. ในกล่องบน (User variables) กด **New**
   - Variable name: `OLLAMA_HOST`
   - Variable value: `0.0.0.0`
4. กด OK ทั้งหมด
5. คลิกขวาไอคอน Ollama ที่มุมขวาล่างของจอ เลือก **Quit** แล้วเปิดโปรแกรม Ollama ใหม่

## ส่วน ง: รันการเปรียบเทียบ

### ง.1 ตรวจสอบความพร้อม

ไฟล์ `.env` ควรมีค่าเหล่านี้ครบตามแบบจำลองที่ต้องการทดสอบ:

```
OPENAI_API_KEY=sk-...            # ถ้าจะทดสอบ OpenAI
GEMINI_API_KEY=AIza...           # ถ้าจะทดสอบ Gemini
GEMINI_MODEL=gemini-2.5-flash
OLLAMA_BASE_URL=http://localhost:11434
TYPHOON_MODEL=scb10x/typhoon2.5-qwen3-4b
```

แบบจำลองใดไม่มีกุญแจ สคริปต์จะข้ามไปเองโดยไม่ทำให้ล้มเหลว

### ง.2 คำสั่งรัน

```powershell
cd D:\project

# รันทุกแบบจำลองที่ตั้งค่าไว้ 1 รอบ
node evaluation/compare-models.js

# ทดสอบเฉพาะบางตัว
node evaluation/compare-models.js --models=gemini
node evaluation/compare-models.js --models=gemini,typhoon

# รันซ้ำ 3 รอบต่อคำถาม เพื่อดูความคงเส้นคงวาของคำตอบ
node evaluation/compare-models.js --runs=3
```

> **แนะนำสำหรับข้อมูลที่จะใส่ในเล่ม:** ใช้ `--runs=3` ขึ้นไป
> เพราะแบบจำลองภาษาให้คำตอบไม่เหมือนเดิมทุกครั้ง การรันรอบเดียวอาจได้ผลที่บังเอิญดีหรือแย่
> การรันหลายรอบทำให้รายงานค่าเฉลี่ยและส่วนเบี่ยงเบนมาตรฐานได้ ซึ่งน่าเชื่อถือกว่ามาก
>
> ระวังโควตาฟรีของ Gemini: 12 คำถาม × 3 รอบ × 2 ครั้งต่อคำถาม (เรียกเครื่องมือ) = 72 คำขอ
> ยังอยู่ในโควตา 250 คำขอต่อวัน แต่ถ้ารันหลายครั้งในวันเดียวอาจชนเพดาน

### ง.2.1 การจัดการโควตาของบริการฟรี

โควตาฟรีของ Gemini จำกัดทั้งจำนวนคำขอต่อนาที (ประมาณ 10 ครั้ง) และต่อวัน (ประมาณ 250 ครั้ง)
สคริปต์จัดการให้อัตโนมัติแล้วสองชั้น

1. **เว้นจังหวะล่วงหน้า** — หน่วงเวลาระหว่างคำขอให้ไม่เกินเพดานต่อนาที
   ค่าเริ่มต้นตั้งไว้ที่ 8 คำขอต่อนาที (เว้น 7.5 วินาทีต่อคำขอ) เพื่อเผื่อระยะปลอดภัย
2. **รอแล้วลองใหม่** — หากยังถูกปฏิเสธด้วยรหัส 429 จะอ่านระยะเวลาที่ Google แนะนำ
   มารอแล้วลองใหม่สูงสุด 4 ครั้ง

**สำคัญต่อความถูกต้องของการวัด:** เวลาที่สคริปต์หน่วงเองและเวลาที่รอลองใหม่
**ไม่ถูกนับ**เข้าเวลาตอบสนอง สคริปต์นับเฉพาะเวลาที่ใช้เรียก API จริงที่สำเร็จเท่านั้น
ตัวเลขเวลาตอบสนองจึงสะท้อนความเร็วของแบบจำลอง ไม่ใช่ความเร็วของสคริปต์

ปรับค่าได้ถ้าจำเป็น โดยเพิ่มบรรทัดนี้ในไฟล์ `.env`:
```
GEMINI_RPM_LIMIT=5
```
หรือสั่งหน่วงเพิ่มทุกคำขอผ่านบรรทัดคำสั่ง:
```powershell
node evaluation/compare-models.js --models=gemini --delay=10000
```

**เก็บผลไว้ทุกครั้งที่รัน**

ไฟล์ผลลัพธ์ตั้งชื่อตามวันเวลาที่รัน จึงไม่ทับกัน เก็บไว้ได้ทั้งหมด

## ส่วน จ: การเขียนผลลงเล่มวิทยานิพนธ์

### จ.1 หัวข้อที่ควรเพิ่มในบทที่ 3

**การคัดเลือกแบบจำลองภาษา**

อธิบายว่าผู้วิจัยได้เปรียบเทียบแบบจำลองภาษา 3 ตัว ที่มีลักษณะการให้บริการต่างกัน คือ
(1) แบบจำลองเชิงพาณิชย์จากต่างประเทศ
(2) แบบจำลองเชิงพาณิชย์ที่มีโควตาให้ใช้ฟรี
(3) แบบจำลองแบบเปิดที่พัฒนาสำหรับภาษาไทยโดยเฉพาะและรันในเครื่องผู้ใช้เองได้

โดยควบคุมตัวแปรอื่นให้คงที่ทั้งหมด แล้ววัดตัวชี้วัด 3 ด้าน ได้แก่
อัตราการเรียกใช้เครื่องมือสำเร็จ ความถูกต้องของคำตอบ และเวลาตอบสนอง

**เกณฑ์การตัดสินใจ**

ระบุว่าเลือกแบบจำลองใดไปใช้ในระบบจริง และเพราะเหตุใด โดยอ้างอิงจากผลการทดลอง
เช่น หากพบว่าแบบจำลองที่รันในเครื่องเรียกใช้เครื่องมือคำนวณได้ไม่แม่นยำพอ
ก็เป็นเหตุผลที่หนักแน่นในการเลือกใช้แบบจำลองบนคลาวด์

### จ.2 ประเด็นอภิปรายที่ควรเขียนในบทสรุป

1. **ความสัมพันธ์ระหว่างขนาดแบบจำลองกับความสามารถในการเรียกใช้เครื่องมือ**
   แบบจำลองขนาดเล็กมักตัดสินใจเรียกเครื่องมือผิดพลาดบ่อยกว่า
   ซึ่งกระทบโดยตรงต่อความน่าเชื่อถือของตัวเลขภาษี

2. **ข้อแลกเปลี่ยนระหว่างความเป็นส่วนตัวกับประสิทธิภาพ**
   แบบจำลองที่รันในเครื่องไม่ส่งข้อมูลผู้เสียภาษีออกนอกองค์กร
   ซึ่งเป็นข้อได้เปรียบสำคัญด้านความเป็นส่วนตัวสำหรับข้อมูลอ่อนไหวอย่างข้อมูลรายได้
   แต่ต้องแลกกับความสามารถที่ด้อยกว่าและเวลาตอบสนองที่ช้ากว่า
   ประเด็นนี้สอดคล้องกับข้อพิจารณาทางจริยธรรมที่ Valvoda และคณะ (2024) เสนอไว้

3. **ความเหมาะสมกับบริบทไทย**
   อภิปรายว่าแบบจำลองที่ฝึกด้วยข้อมูลภาษาไทยโดยเฉพาะ ให้คำตอบที่เป็นธรรมชาติกว่าหรือไม่
   และเชื่อมโยงกับงานของ Akarajaradwong และคณะ (2025)
   ที่ศึกษาการปรับปรุงแบบจำลองภาษาสำหรับการตอบคำถามกฎหมายไทยโดยเฉพาะ

4. **ความยั่งยืนของระบบ**
   หากหน่วยงานภาครัฐจะนำระบบนี้ไปใช้จริง การพึ่งพาบริการเชิงพาณิชย์จากต่างประเทศ
   มีความเสี่ยงด้านค่าใช้จ่ายระยะยาวและการเปลี่ยนแปลงเงื่อนไขบริการ
   ผลการทดลองนี้ช่วยประเมินว่าทางเลือกแบบเปิดพร้อมใช้งานจริงแล้วหรือยัง

### จ.3 ข้อจำกัดของการทดลองที่ต้องระบุ

1. ชุดคำถามทดสอบมี 12 ข้อ ซึ่งครอบคลุมหัวข้อหลักแต่ยังไม่ครอบคลุมทุกกรณีการใช้งาน
2. การตรวจความถูกต้องเชิงเนื้อหาใช้วิธีตรวจคำสำคัญ ซึ่งอาจตัดสินผิดในกรณีที่คำตอบถูกต้อง
   แต่ใช้คำอื่นที่มีความหมายเดียวกัน จึงควรให้ผู้เชี่ยวชาญด้านภาษีตรวจทานคำตอบประกอบด้วย
3. เวลาตอบสนองของแบบจำลองบนคลาวด์ขึ้นกับคุณภาพอินเทอร์เน็ตขณะทดสอบ
   ควรระบุช่วงเวลาและสภาพเครือข่ายที่ใช้เก็บข้อมูล
4. แบบจำลองที่รันในเครื่องถูกจำกัดด้วยหน่วยความจำกราฟิก 4 GB
   ผลที่ได้จึงสะท้อนความสามารถของแบบจำลองขนาด 4 พันล้านพารามิเตอร์เท่านั้น
   ไม่ได้สะท้อนศักยภาพสูงสุดของตระกูลแบบจำลองนั้น
5. ผู้ให้บริการอาจปรับปรุงแบบจำลองโดยไม่เปลี่ยนชื่อรุ่น ผลการทดลองจึงผูกกับช่วงเวลาที่เก็บข้อมูล
   ต้องระบุวันที่ทดสอบไว้ในรายงานทุกครั้ง

### วิธีเพิ่มคำถามใหม่

เปิดไฟล์ `evaluation/test-questions.json` แล้วเพิ่มรายการในรูปแบบนี้:

```json
{
  "id": "Q13",
  "category": "หมวดของคำถาม",
  "question": "ข้อความคำถาม",
  "requiresTool": false,
  "check": "keywords",
  "expected": ["คำสำคัญที่ต้องมี"],
  "note": "เหตุผลที่เพิ่มคำถามนี้"
}
```

```powershell
node -e "const c=require('./n8n/tools/tax-calculator');console.log(JSON.stringify(c.calculateThaiPIT({income:{salary:800000},allowances:{socialSecurity:9000}})['สรุป'],null,2))"
```
