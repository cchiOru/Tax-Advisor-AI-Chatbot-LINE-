# สรุประบบสำหรับนำเสนอ

**ระบบที่ปรึกษาด้านภาษีด้วยปัญญาประดิษฐ์บนไลน์ โดยใช้ระบบอัตโนมัติ**
ปรับปรุงล่าสุด 5 สิงหาคม 2569

---

## ระบบนี้ต่างจากการถาม ChatGPT อย่างไร

คำถามนี้คือหัวใจของงาน และคำตอบไม่ใช่ "ระบบเราฉลาดกว่า"

> **ระบบนี้คือ AI ที่ไม่คิดเลขเอง**
> ตัวเลขภาษีทุกตัวมาจากโปรแกรมที่ผ่านการทดสอบ ไม่ได้มาจากการทำนายของแบบจำลองภาษา

**หลักฐานว่าจำเป็น** จากการวัดจริงของระบบนี้ เมื่อแบบจำลองภาษาไม่เรียกเครื่องคำนวณ
แล้วคิดเลขเอง มันตอบว่า

```
600,000 − 9,000 − 100,000 − 60,000 = 431,000  →  ภาษี 45,500 บาท
```

ลืมหักค่าใช้จ่าย 100,000 บาท และลืมค่าลดหย่อนส่วนตัว 60,000 บาท
คำตอบดูน่าเชื่อ มีขั้นตอนครบ อ้างมาตรา 47(1)(ง) ถูกต้อง **แต่ตัวเลขผิด**

นี่คือสิ่งที่เกิดขึ้นทุกครั้งเมื่อถาม ChatGPT หรือ Gemini เรื่องคำนวณภาษี
เพราะแบบจำลองภาษาไม่ได้คำนวณ แต่ทำนายตัวอักษรถัดไป

---

## สถาปัตยกรรม

```
ผู้ใช้ LINE
   ↓
จำแนกเจตนาด้วยกฎ (ไม่ใช่ให้ AI ตัดสิน)
   ↓
   ├── เส้นทางตัวเลข  → เครื่องคำนวณภาษี (โค้ด ผ่านทดสอบ 40 ข้อ)
   ├── เส้นทางความรู้  → ฐานความรู้ 80 รายการ (อ้างมาตราได้ทุกข้อ)
   └── เส้นทางตัวบท    → ประมวลรัษฎากร 309 มาตรา (อ้างถ้อยคำเท่านั้น)
   ↓
แบบจำลองภาษา (ทำหน้าที่เรียบเรียงเป็นภาษาคนเท่านั้น)
   ↓
บังคับด้วยโค้ด: ตัดความยาวไม่เกิน 450 ตัวอักษร + ต่อคำเตือน 1161 ทุกครั้ง
   ↓
ตอบกลับผ่าน LINE
```

**เทคโนโลยี** n8n Workflow Automation · PostgreSQL · LINE Messaging API ·
Google Gemini (gemini-3-flash-preview) และ Typhoon 2.5 4B รันในเครื่องผ่าน Ollama · Docker

## ข้อค้นพบสำคัญ 3 ข้อ

### 1. สั่งด้วยคำสั่งระบบไม่พอ ต้องบังคับด้วยกฎ

ระบบสั่งไว้ชัดเจนในคำสั่งระบบว่า "ต้องเรียกเครื่องมือคำนวณเสมอ"
แต่แบบจำลองเชื่อฟังเพียง **79.5%** ที่เหลือมันเลือกคิดเลขเอง

เมื่อย้ายการตัดสินใจนี้ออกจากแบบจำลอง ไปให้**กฎที่ตรวจสอบได้**เป็นผู้บังคับ
โดยต่อคำสั่งกำกับท้ายคำถามอัตโนมัติเมื่อระบบจำแนกได้ว่าเป็นคำถามคำนวณ
อัตราการเรียกเครื่องมือขึ้นเป็น **94.9%** ในการวัดแบบควบคุมตัวแปร
และขึ้นถึง **100%** ในระบบฉบับสมบูรณ์เมื่อใช้ Gemini

หลักการเดียวกันใช้ได้ผลกับอีกสองเรื่อง

| เรื่อง | ตอนขอในคำสั่งระบบ | ตอนบังคับด้วยโค้ด |
|---|---|---|
| เรียกเครื่องคำนวณ | 79.5% | 94.9% |
| คำเตือนกรมสรรพากร 1161 | บางครั้งลืม | 100% |
| ความยาวคำตอบ | 729 ตัวอักษร | 404 ตัวอักษร |

### 2. ความยาวคำสั่งระบบมีผลต่อความน่าเชื่อถือโดยตรง

| ความยาวคำสั่งระบบ | จำนวนข้อที่ไม่เรียกเครื่องมือ |
|---|---|
| 2,275 ตัวอักษร | 2 ข้อ |
| 3,321 ตัวอักษร | 3 ข้อ |
| 4,017 ตัวอักษร | 8 ข้อ |

การเพิ่มกฎเข้าไปในคำสั่งระบบด้วยความหวังดี กลับทำให้แบบจำลองขนาดเล็ก
ลืมกฎที่สำคัญกว่า การเขียนคำสั่งจึงต้องคำนึงถึงลำดับและความยาว
ไม่ใช่แค่ความครบถ้วน

### 3. ตัวบทกฎหมายกับตัวเลขที่ใช้จริงไม่ตรงกัน

ประมวลรัษฎากร **มาตรา 47(1)(ง)** เขียนว่าเบี้ยประกันชีวิตหักลดหย่อนได้ไม่เกิน **10,000 บาท**
แต่จำนวนที่ใช้จริงคือ **100,000 บาท** ตามกฎกระทรวง ฉบับที่ 126 ข้อ 2(61)

ถ้านำตัวบทดิบมาให้ระบบค้นเพื่อตอบผู้ใช้ ระบบจะตอบ 10,000 บาท
พร้อมอ้างมาตราถูกต้องเป๊ะ ซึ่งเป็นความผิดพลาดที่ผู้ใช้ตรวจจับไม่ได้

ระบบจึงแยกฐานข้อมูลออกเป็นสองส่วนตามหน้าที่

| ตาราง | จำนวน | หน้าที่ |
|---|---|---|
| `tax_law_knowledge` | 80 | ตอบคำถามผู้ใช้ ตัวเลขที่ใช้จริงปีภาษี 2567 |
| `revenue_code_current` | 309 | อ้างถ้อยคำของกฎหมายเมื่อผู้ใช้ถามถึงมาตราโดยตรง |

## ข้อจำกัดที่ยังมีอยู่ (ระบุตรงไปตรงมา)

1. **ยังไม่ควรเปิดให้ประชาชนทั่วไปใช้** เพราะคำถาม 115 ข้อเป็นชุดที่ผู้จัดทำสร้างเอง ยังไม่เคยเจอคำถามจากผู้ใช้จริง แปลว่า
   ยังมีโอกาสที่ระบบตอบตัวเลขโดยไม่ผ่านเครื่องคำนวณ ซึ่งเป็นความเสี่ยงสูงสุดของระบบนี้
2. **ฮาร์ดแวร์ที่ใช้ทดลองไม่พอสำหรับแบบจำลองในเครื่อง** NVIDIA RTX 3050 VRAM 4 GB
   ทำให้ Typhoon ต้องแบ่งประมวลผลกับ CPU ปรับจูนแล้วดีขึ้นจาก 44% เป็น 66% บน GPU
   แต่ยังเข้าไม่หมด
3. **ครอบคลุมเฉพาะภาษีเงินได้บุคคลธรรมดา** ภาษีประเภทอื่นตอบได้เชิงหลักเกณฑ์
   แต่ระบบถูกออกแบบให้ปฏิเสธการคำนวณ เพราะไม่มีเครื่องมือรองรับ
4. **ยังไม่มีข้อหารือกรมสรรพากร** ซึ่งเป็นแหล่งที่ตอบคำถามเคสจริงของประชาชนได้ดีที่สุด
5. **ฐานความรู้ยึดปีภาษี 2567** มาตรการลดหย่อนเปลี่ยนทุกปี ต้องมีแผนปรับปรุง
