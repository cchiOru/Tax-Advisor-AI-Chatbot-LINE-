## ลิสต์ที่ต้องทำ เรียงตามลำดับ

### 0. นำเข้าฐานความรู้ชุดใหม่เข้าฐานข้อมูล  ← ทำก่อนวัด

ฐานความรู้ขยายจาก 21 เป็น 80 รายการ ครอบคลุมกฎหมายภาษีทั้งระบบและสถานการณ์จริงของผู้เสียภาษี

```powershell
cd D:\project
docker cp postgres\seed-tax-law-full.sql tax-advisor-postgres:/tmp/full.sql
docker exec -it tax-advisor-postgres psql -U n8n_admin -d tax_advisor -f /tmp/full.sql
docker cp postgres\seed-tax-law-cases.sql tax-advisor-postgres:/tmp/cases.sql
docker exec -it tax-advisor-postgres psql -U n8n_admin -d tax_advisor -f /tmp/cases.sql
docker cp postgres\seed-tax-forms.sql tax-advisor-postgres:/tmp/forms.sql
docker exec -it tax-advisor-postgres psql -U n8n_admin -d tax_advisor -f /tmp/forms.sql
```

**ตัวบทประมวลรัษฎากรฉบับปัจจุบัน (ทางเลือก ทำทีหลังได้)**

```powershell
pip install requests beautifulsoup4
python postgres/import-revenue-code-current.py
docker cp postgres\seed-revenue-code-current.sql tax-advisor-postgres:/tmp/rc.sql
docker exec -it tax-advisor-postgres psql -U n8n_admin -d tax_advisor -f /tmp/rc.sql
```

ดึงทุกมาตรา ทุกทวิ ทุกวรรค จาก rd.go.th เก็บลงตาราง `revenue_code_current` แยกต่างหาก
**ไม่ปนกับฐานความรู้ที่ใช้ตอบตัวเลข** เหตุผลอยู่ในหัวไฟล์สคริปต์

(ชื่อผู้ใช้ n8n_admin มาจากค่า POSTGRES_USER ในไฟล์ .env)

ตรวจว่าเข้าครบ

```powershell
docker exec -it tax-advisor-postgres psql -U n8n_admin -d tax_advisor -c "SELECT count(*) FROM tax_law_knowledge;"
```

ต้องได้ 80 รายการ ถ้าได้ 91 แสดงว่าคำสั่งลบรายการซ้ำยังไม่ทำงาน ให้รันไฟล์ full อีกครั้ง

แล้วนำเข้าเวิร์กโฟลว์ใหม่ด้วย เพราะเพิ่มคำสำคัญจาก 116 เป็น 322 คู่
ถ้าไม่นำเข้า ระบบจะค้นข้อมูลชุดใหม่ไม่เจอ

### 1. วัด Gemini ให้ครบ 32 ข้อ  ← งานหลัก

`gemini-3-flash-preview` คือตัวที่จะใช้จริง ตัวเลขของมันจึงเป็นตัวตัดสินว่าระบบพร้อมหรือยัง
โควตาฟรีรีเซ็ตเที่ยงคืนเวลาแปซิฟิก (ประมาณ 14:00 น. บ้านเรา)

```powershell
cd D:\project
node evaluation/run-accuracy-test.js --model=gemini
```

**ไม่ต้องใส่ `--fresh`** ระบบจะวัดต่อจากข้อที่ค้างไว้เอง
ถ้าโควตาหมดอีก ให้รันซ้ำวันถัดไป ผลจะต่อกันเป็นชุดเดียว

ก่อนวัด ตั้ง `ACTIVE_MODEL_NAME=gemini-3-flash-preview` ใน `.env`
และเลือก Google Gemini Chat Model ในเวิร์กโฟลว์ n8n ให้ตรงกัน

### 2. Typhoon — ทดสอบไปเรื่อย ๆ ไม่ต้องรีบ

แก้หน้าต่างบริบทแล้ว (`typhoon-tax`, num_ctx 16384) เริ่มตอบถูก แต่ช้ามาก ~150 วินาทีต่อข้อ

**ข้อสรุปเบื้องต้นที่มีค่าต่อเล่ม** Typhoon แม่นขึ้นได้ แต่เกิน 60 วินาที
แปลว่าใช้กับ LINE จริงไม่ได้ เพราะ reply token หมดอายุก่อน
นี่คือหลักฐานว่าการเลือกแบบจำลองต้องดูทั้งความแม่นยำและเวลาตอบสนอง ไม่ใช่ดูความแม่นยำอย่างเดียว

ถ้าอยากลองให้เร็วขึ้น ลด `num_ctx` เหลือ 8192 ใน `n8n/ollama/Modelfile.typhoon-tax`
แล้วสร้างใหม่ + วัดด้วย `--fresh` (ต้องใส่ เพราะระบบแยกไม่ออกว่าเป็นคนละการตั้งค่า)

**เก็บผลทุกชุดไว้** ทั้ง 28.1% ตอนบริบทถูกตัด และผลหลังแก้ เป็นหลักฐานเปรียบเทียบก่อน-หลัง

### 3. ตัดสินใจตามเกณฑ์

ต้องผ่านครบทั้งสามด้าน เครื่องมือวัดสรุปให้ท้ายผลอยู่แล้ว

| ด้าน | เกณฑ์ | ถ้าไม่ผ่านต้องแก้ที่ |
|---|---|---|
| ความถูกต้อง | ≥ 80% (เป้า 90%) | ฐานความรู้ / คำสั่งระบบ / เปลี่ยนแบบจำลอง |
| เรียกเครื่องมือคำนวณ | ≥ 98% | คำอธิบายเครื่องมือใน `n8n/build-workflow.py` |
| ความไวในการตอบ | ไม่มีข้อไหนเกิน 60 วินาที | เปลี่ยนแบบจำลองให้เร็วขึ้น |
| ฐานความรู้ครอบคลุม | ค้นเจอ ≥ 90% ของคำถาม | `postgres/seed-tax-law-extra.sql` + `DOMAIN_KEYWORDS` |

**ผ่านครบแล้วค่อยเริ่มแก้เล่มรายงาน** ไม่ใช่ก่อนหน้านั้น

รายละเอียดการอ่านผลและวิธีแก้แต่ละกรณี: `docs/08-ความแม่นยำและการนำไปใช้จริง.md`
