## ส่วน ข: สำรองข้อมูลก่อนเริ่ม

> ทำขั้นตอนนี้ทุกครั้งก่อนแก้ไขฐานข้อมูล ถ้ามีอะไรผิดพลาดจะย้อนกลับได้

1. เปิด **PowerShell** (กด Start พิมพ์ `PowerShell` แล้ว Enter)
2. เข้าโฟลเดอร์โปรเจกต์:
   ```powershell
   cd D:\project
   ```
3. สร้างโฟลเดอร์เก็บไฟล์สำรอง:
   ```powershell
   mkdir backup -Force
   ```
4. สำรองฐานข้อมูลทั้งหมด (แทน `n8n_admin` ด้วยค่า `POSTGRES_USER` ในไฟล์ `.env` ของคุณ)

   ให้เขียนไฟล์ไว้ใน container ก่อน แล้วค่อยคัดลอกออกมา **สองคำสั่งนี้ต้องทำทั้งคู่**:
   ```powershell
   docker exec tax-advisor-postgres pg_dumpall -U n8n_admin -f /tmp/backup.sql
   docker cp tax-advisor-postgres:/tmp/backup.sql backup\backup-before-v2.sql
   ```

   > **ห้ามใช้เครื่องหมาย `>` เปลี่ยนทิศทางไฟล์** เช่น `docker exec ... pg_dumpall > backup.sql`
   > เพราะ Windows PowerShell รุ่น 5.1 จะบันทึกไฟล์เป็นรหัสอักขระ UTF-16
   > ซึ่ง `psql` อ่านกลับไม่ได้ ทำให้ไฟล์สำรองใช้กู้ข้อมูลจริงไม่ได้เลย
   > วิธีสองคำสั่งด้านบนได้ไฟล์ที่ตรงกับต้นฉบับทุกไบต์

5. ตรวจสอบว่าไฟล์ใช้ได้จริง:
   ```powershell
   dir backup
   Get-Content backup\backup-before-v2.sql -TotalCount 3
   ```
   - ขนาดไฟล์ต้องมากกว่า 0 (ปกติหลายร้อย KB)
   - สามบรรทัดแรกต้องอ่านออกเป็นข้อความ SQL เช่น `--` หรือ `SET ...`
     ถ้าเห็นเป็นอักขระประหลาดหรือมีช่องว่างแทรกทุกตัวอักษร แปลว่าไฟล์เป็น UTF-16 ให้ทำข้อ 4 ใหม่

> **หมายเหตุ:** ถ้าคำสั่งขึ้น error ว่าไม่รู้จัก user ให้เปิดไฟล์ `.env` ดูค่า `POSTGRES_USER` แล้วใช้ค่านั้นแทน

## ส่วน ค: อัปเดตโครงสร้างฐานข้อมูล

ขั้นตอนนี้เพิ่มคอลัมน์สำหรับเก็บข้อมูลเชิงวิจัย (เวลาตอบสนอง ผลการสืบค้น) โดย**ไม่ลบข้อมูลเดิม**

1. คัดลอกไฟล์ migration เข้าไปใน container:
   ```powershell
   docker cp postgres\migrations\001-add-research-fields.sql tax-advisor-postgres:/tmp/m001.sql
   ```
2. รันไฟล์ (แทน `n8n_admin` ด้วยค่าของคุณ):
   ```powershell
   docker exec -it tax-advisor-postgres psql -U n8n_admin -d tax_advisor -f /tmp/m001.sql
   ```
3. ผลลัพธ์ที่ควรเห็นท้ายสุด คือรายชื่อคอลัมน์ของตาราง `conversations` ซึ่งต้องมีคอลัมน์เหล่านี้ครบ:
   - `response_time_ms`
   - `matched_knowledge`
   - `knowledge_hits`
   - `model_name`

   ถ้าเห็นครบ แปลว่าสำเร็จ

> **ถ้าขึ้นข้อความ `NOTICE: relation "..." already exists, skipping`** ไม่ต้องตกใจ เป็นเรื่องปกติ
> สคริปต์นี้ออกแบบให้รันซ้ำได้โดยไม่เสียหาย

## ส่วน ง: เติมฐานความรู้กฎหมายภาษี

ขั้นตอนนี้ใส่ข้อมูลกฎหมายภาษี 13 รายการ (แบ่งเป็น 8 หมวด) ลงฐานข้อมูล เพื่อให้ระบบค้นมาใช้ตอบคำถามได้

1. คัดลอกไฟล์เข้า container:
   ```powershell
   docker cp postgres\seed-tax-law.sql tax-advisor-postgres:/tmp/seed.sql
   ```
2. รันไฟล์:
   ```powershell
   docker exec -it tax-advisor-postgres psql -U n8n_admin -d tax_advisor -f /tmp/seed.sql
   ```
3. ท้ายสุดจะเห็นตารางสรุปแบบนี้ (จำนวนอาจต่างเล็กน้อย):
   ```
        category        | จำนวนรายการ
   ---------------------+-------------
    กำหนดการยื่นภาษี      |           2
    การคืนภาษี           |           1
    ค่าลดหย่อนภาษี        |           3
    ภาษีเงินได้บุคคลธรรมดา |           2
    ...
   ```
   ถ้าเห็นตารางนี้แปลว่าสำเร็จ

> **หมายเหตุ:** ไฟล์นี้จะล้างตาราง `tax_law_knowledge` แล้วใส่ใหม่ทุกครั้งที่รัน
> ทำแบบนี้เพื่อไม่ให้ข้อมูลซ้ำเวลารันหลายรอบ ข้อมูลบทสนทนาและผู้ใช้ไม่ได้รับผลกระทบ

## ส่วน จ: สร้าง Credential ของ OpenAI ใน n8n

เวอร์ชัน 2 ใช้ node ของ n8n ที่ต้องมี credential แบบ OpenAI โดยเฉพาะ (ต่างจากเวอร์ชัน 1 ที่ยิง HTTP ตรง)

1. เปิดเบราว์เซอร์ไปที่ http://localhost:5678 แล้วล็อกอิน
2. พิมพ์ที่แถบที่อยู่: `localhost:5678/home/credentials` แล้ว Enter
3. กดปุ่ม **Add Credential** (มุมขวาบน)
4. ในช่องค้นหา พิมพ์ `OpenAi` แล้วเลือกรายการชื่อ **OpenAi**
5. ในช่อง **API Key** ให้ใส่ค่าเดียวกับ `OPENAI_API_KEY` ในไฟล์ `.env`
   - เปิดไฟล์ `.env` ด้วย VS Code หรือ Notepad คัดลอกค่าหลังเครื่องหมาย `=` มาวาง
   - ระวังอย่าให้มีช่องว่างหรือเครื่องหมายคำพูดติดมา
6. กด **Save**
7. คลิกที่ชื่อ credential ด้านบนของหน้าต่าง แก้ชื่อเป็น `OpenAI API` แล้วกด Save อีกครั้ง

> **ตรวจสอบ:** ถ้า n8n ขึ้นเครื่องหมายถูกสีเขียวหรือไม่มีข้อความแดง แปลว่า key ใช้งานได้
> ถ้าขึ้น error เรื่อง authentication ให้ตรวจสอบว่า key ถูกต้องและบัญชี OpenAI มีเครดิตเหลือ

## ส่วน ฉ: นำเข้าและตั้งค่า Workflow เวอร์ชัน 2

### ฉ.1 ปิด Workflow เวอร์ชันเก่าก่อน

> **สำคัญมาก:** workflow ทั้งสองเวอร์ชันใช้ที่อยู่ webhook เดียวกัน (`/webhook/line-webhook`)
> ถ้าเปิดทำงานพร้อมกันจะชนกันและระบบทำงานผิดพลาด

1. ไปที่ `localhost:5678/home/workflows`
2. เปิด workflow ชื่อ **Tax Advisor AI Chatbot (LINE)** (อันเก่า)
3. ที่มุมขวาบน กดสวิตช์ให้เปลี่ยนจาก **Published** (เขียว) เป็นสถานะปิด
4. ถ้ามี workflow เก่าหลายอัน ให้ปิดให้หมดทุกอัน

### ฉ.2 นำเข้า Workflow เวอร์ชัน 2

1. กลับไปที่หน้า **Workflows**
2. กดปุ่มลูกศรข้างปุ่ม **Add workflow** (มุมขวาบน) แล้วเลือก **Import from File**
3. เลือกไฟล์ `D:\project\n8n\workflows\tax-advisor-workflow.json`
4. จะได้ workflow ใหม่ชื่อ **Tax Advisor AI Chatbot (LINE) v2** มี 14 node

### ฉ.3 ผูก Credential ให้ครบทุก node

มี node ที่ต้องผูก credential ทั้งหมด **5 node** ทำทีละอันตามตารางนี้:

| ลำดับ | ชื่อ node | สัญลักษณ์ | ต้องเลือก credential |
|---|---|---|---|
| 1 | **Upsert User** | รูปช้าง | `Tax Advisor Postgres` |
| 2 | **Search Tax Knowledge** | รูปช้าง | `Tax Advisor Postgres` |
| 3 | **Log Conversation** | รูปช้าง | `Tax Advisor Postgres` |
| 4 | **Postgres Chat Memory** | รูปช้าง (อยู่ด้านล่าง) | `Tax Advisor Postgres` |
| 5 | **OpenAI Chat Model** | รูปวงกลม (อยู่ด้านล่าง) | `OpenAI API` |

วิธีทำแต่ละ node:

1. ดับเบิลคลิกที่ node
2. มองหาช่องบนสุดชื่อ **Credential to connect with**
3. คลิกที่ช่องนั้น แล้วเลือกชื่อ credential ตามตาราง
4. ปิดหน้าต่างด้วยการกดปุ่ม X มุมขวาบนของ panel (หรือกดปุ่ม Esc)
5. ทำซ้ำจนครบทั้ง 5 node

> **จุดสังเกต:** node ที่ยังไม่ได้ผูก credential จะมีสามเหลี่ยมสีแดงเล็กๆ ที่มุม
> เมื่อผูกครบทุกอันแล้ว สามเหลี่ยมแดงต้องหายไปหมด

### ฉ.4 ตรวจสอบ node ที่ไม่ต้องแก้อะไร

node เหล่านี้ทำงานได้เลย ไม่ต้องตั้งค่าเพิ่ม แต่ควรเปิดดูเพื่อทำความเข้าใจ (มีคำอธิบายไทยกำกับไว้ในช่อง Notes ของทุก node):

- **Tax Calculator Tool** — เครื่องคำนวณภาษี โค้ดถูกฝังไว้แล้วครบถ้วน
- **AI Agent (Tax Advisor)** — สมองของระบบ มีคำสั่งควบคุมพฤติกรรม (system prompt) อยู่ข้างใน
- **Reply to LINE** และ **Respond OK to LINE** — ใช้ token จากไฟล์ `.env` อัตโนมัติ

### ฉ.5 บันทึกและเปิดใช้งาน

1. กด **Ctrl+S** เพื่อบันทึก
2. กดปุ่ม **Publish** (มุมขวาบน) ให้เปลี่ยนเป็นสถานะ **Published** สีเขียว

## ส่วน ช: ทดสอบระบบ

### ช.1 ตรวจสอบ Webhook URL

> ถ้าคุณปิด-เปิด Docker ใหม่ ngrok จะได้ URL ใหม่ ต้องอัปเดตใน LINE ทุกครั้ง

1. เปิด http://localhost:4040 ดูค่าในช่อง **URL** (รูปแบบ `https://xxxxx.ngrok-free.dev`)
2. ถ้า URL ไม่เหมือนเดิม ให้ไปที่ https://developers.line.biz/console/ → Channel → แท็บ **Messaging API**
3. แก้ **Webhook URL** เป็น `<URL ใหม่>/webhook/line-webhook` แล้วกด **Update** และ **Verify**
4. ต้องขึ้น **Success** สีเขียว

### ช.2 ทดสอบด้วยคำถามพื้นฐาน

เปิดแชท LINE กับบอท แล้วพิมพ์ทีละข้อความ รอคำตอบก่อนส่งข้อความถัดไป:

| ลำดับ | พิมพ์ว่า | สิ่งที่ควรได้ |
|---|---|---|
| 1 | `ค่าลดหย่อนบุตรได้เท่าไหร่` | ตอบ 30,000 บาท/คน และอธิบายกรณีบุตรคนที่ 2 ที่เกิดตั้งแต่ปี 2561 |

### ปัญหา 1: บอทตอบตัวเลขภาษีผิด หรือไม่ตรงกับที่ทดสอบไว้

**สาเหตุ:** AI ไม่ได้เรียกใช้เครื่องมือคำนวณ แต่คำนวณเอง

**วิธีตรวจสอบ:**

**วิธีแก้:**
1. ตรวจสอบว่า node **Tax Calculator Tool** มีเส้นเชื่อมไปที่ AI Agent จริง (เส้นประด้านล่าง)
2. ถ้าไม่มีเส้น ให้ลากเส้นจากจุดเชื่อมของ Tool ขึ้นไปที่ช่อง **Tool** ใต้ AI Agent

### ปัญหา 2: บอทจำบทสนทนาไม่ได้

```sql
SELECT session_id, COUNT(*) FROM n8n_chat_histories GROUP BY session_id;
```

ถ้าไม่มีข้อมูลเลย แปลว่า Postgres Chat Memory ไม่ทำงาน

3. ตรวจสอบว่ามีเส้นเชื่อมจาก node นี้ไปยังช่อง **Memory** ของ AI Agent

### ปัญหา 4: บอทตอบว่าไม่พบข้อมูลในฐานความรู้ตลอด

```sql
SELECT COUNT(*) FROM tax_law_knowledge;
```
ต้องได้ 13 รายการ ถ้าได้ 0 แปลว่ายังไม่ได้เติมข้อมูล

> ซึ่งตัดคำภาษาไทยได้ไม่สมบูรณ์เท่าเครื่องมือตัดคำเฉพาะทาง จึงอาจค้นไม่เจอในบางคำถาม

### ปัญหา 5: node OpenAI Chat Model ขึ้น error `Could not get parameter`

**อาการ:** ใน Executions เห็นวงกลมกากบาทสีแดงที่ node **OpenAI Chat Model**
เวลาประมวลผลเร็วผิดปกติ (ต่ำกว่า 1 วินาที) และบอทตอบข้อความสำรองว่าระบบขัดข้อง

**สาเหตุ:** n8n รุ่นใหม่ (พบในรุ่น 2.12.3) เปลี่ยนช่อง **Model** ของ node นี้
จากการรับค่าเป็นข้อความธรรมดา มาเป็นตัวเลือกแบบ resource locator
ไฟล์ workflow ที่สร้างจากรุ่นเก่าจึงส่งค่าในรูปแบบที่ node อ่านไม่ออก

**วิธีสังเกต:** ช่อง Model จะมีดรอปดาวน์เขียนว่า `Mode...` อยู่ทางซ้าย
และชื่อโมเดลแสดงเป็นตัวอักษรจางๆ (เป็นข้อความตัวอย่าง ไม่ใช่ค่าที่ตั้งไว้จริง)

**วิธีแก้ (ทำในหน้าจอ n8n ได้เลย):**
1. ดับเบิลคลิก node **OpenAI Chat Model**
2. ที่ช่อง Model คลิกดรอปดาวน์ `Mode...` เลือก **From list** แล้วเลือก `gpt-4o-mini`
   - ถ้ารายการไม่ขึ้น ให้เลือก mode เป็น **ID** แล้วพิมพ์ `gpt-4o-mini` เอง
3. ปิด panel → กด **Ctrl+S** → กด **Publish**

> ไฟล์ `n8n/build-workflow.py` ในโปรเจกต์นี้แก้ให้รองรับรูปแบบใหม่แล้ว
> หาก import ไฟล์ที่สร้างใหม่จะไม่พบปัญหานี้อีก

2. ฐานความรู้ครอบคลุม 13 รายการใน 8 หมวดหลัก ยังไม่ครอบคลุมประมวลรัษฎากรทั้งฉบับ
3. เครื่องคำนวณรองรับกรณีทั่วไป ยังไม่รองรับกรณีเฉพาะ เช่น การแยกยื่นของคู่สมรส หรือเงินได้จากต่างประเทศ
4. อัตราภาษีและค่าลดหย่อนอ้างอิงปีภาษี 2567 หากกรมสรรพากรประกาศเปลี่ยนแปลง ต้องปรับปรุงทั้งโค้ดและชุดทดสอบ
5. ระบบใช้ ngrok ซึ่งเหมาะกับการพัฒนาและทดสอบ ยังไม่ใช่สภาพแวดล้อมสำหรับให้บริการจริง
6. การประเมินความถูกต้องของคำตอบเชิงเนื้อหายังต้องอาศัยผู้เชี่ยวชาญด้านภาษีตรวจสอบ

### ฎ.5 แนวทางพัฒนาต่อ

1. เปลี่ยนการสืบค้นเป็นแบบ Vector Search ร่วมกับ embedding ภาษาไทย เช่น BGE-M3 ตามแนวทางของ Akarajaradwong และคณะ (2025)
2. เพิ่มฐานความรู้จากข้อหารือของกรมสรรพากรเพื่อรองรับคำถามเชิงลึก
3. เพิ่มการอ้างอิงเลขมาตราในคำตอบทุกครั้ง แล้ววัดค่า Citation-F1 เปรียบเทียบกับงานวิจัยที่เกี่ยวข้อง
4. ย้ายจาก ngrok ไปใช้เซิร์ฟเวอร์จริงพร้อมโดเมนถาวร
5. เพิ่ม Rich Menu บน LINE เพื่อให้ผู้ใช้เข้าถึงฟังก์ชันหลักได้เร็วขึ้น

## ภาคผนวก: คำสั่งที่ใช้บ่อย

```powershell
# เข้าโฟลเดอร์โปรเจกต์
cd D:\project

# เปิดระบบ
docker compose --profile ngrok up -d

# ดูสถานะ
docker compose ps

# ดู log ของ n8n แบบเรียลไทม์ (กด Ctrl+C เพื่อออก)
docker compose logs -f n8n

# รีสตาร์ทเฉพาะ n8n
docker compose restart n8n

# ปิดระบบ (ข้อมูลยังอยู่)
docker compose down

# เข้าฐานข้อมูล
docker exec -it tax-advisor-postgres psql -U n8n_admin -d tax_advisor

# สำรองฐานข้อมูล
docker exec tax-advisor-postgres pg_dumpall -U n8n_admin > backup\backup.sql

# รันชุดทดสอบ
node --test tests/test-tax-calculator.js

# ประกอบ workflow ใหม่หลังแก้โค้ดคำนวณ
python n8n/build-workflow.py
```

## หมายเหตุด้านความปลอดภัย

ไฟล์ `.env` มีกุญแจลับทั้งหมดของระบบ (API key ของ OpenAI, token ของ LINE)
**ห้ามอัปโหลดไฟล์นี้ขึ้น GitHub เด็ดขาด** ไฟล์ `.gitignore` ในโปรเจกต์นี้ป้องกันไว้ให้แล้ว

หากเคยอัปโหลดไฟล์ `.env` ขึ้น repository สาธารณะไปแล้ว ให้ถือว่ากุญแจทั้งหมดรั่วไหล
และต้องออกกุญแจใหม่ทันที:

1. **OpenAI:** เข้า https://platform.openai.com/api-keys กด Revoke กุญแจเดิม แล้วสร้างใหม่
2. **LINE:** เข้า LINE Developers Console → Messaging API → กด **Issue** เพื่อออก token ใหม่
3. **ngrok:** เข้า Dashboard → Your Authtoken → กด Reset
4. นำค่าใหม่ทั้งหมดใส่ในไฟล์ `.env` แล้วรีสตาร์ท: `docker compose restart n8n`

> การลบไฟล์ออกจาก repository อย่างเดียวไม่พอ เพราะประวัติการ commit ยังเก็บค่าเดิมไว้
> ต้องออกกุญแจใหม่เท่านั้นจึงจะปลอดภัย
